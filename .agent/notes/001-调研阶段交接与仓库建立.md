## 关键结论

这五条是整个调研里最要紧的，展开见 `survey/00`。

1. **三档合规政策。** 第一档全禁（CVPR 2026、ECCV 2026、Elsevier、NIH，离线模型也点名禁了）；第二档允许把稿件喂给隐私合规模型做理解与润色、但不许让它评判（ICML 2026 Policy B）；第三档只许润色自己写的意见并要披露（Wiley、Springer Nature、ARR、ICLR 2026）。NeurIPS 介于一三档之间，稿件全禁、自己写的意见可以查语法。第 0 步永远是查这次会议的指南定档，没定档不开模型。
2. **违规今年已经可被机器检出，而且真的罚了人。** ICML 2026 在投稿 PDF 里埋隐藏水印短语，审稿人把 PDF 丢给模型时模型会被诱导把短语写进评审，多数模型检出率超 80%，全部经人工复核，查实约 795 条违规评审、506 名审稿人，其中 398 名互惠审稿人共 497 篇投稿被 desk reject。ICLR 2026 和 CVPR 2026 的处罚落点一样。
3. **唯一有大规模随机对照证据的用法，是让 AI 审你已经写好的意见。** ICLR 2025 对两万余份评审做反馈，26.6% 的审稿人据此改了评审，共采纳 12222 条建议，盲审认定修改后更清晰更具体。注意这是「审已写好的意见」，不是「让它写意见」。
4. **引用核查的投入产出比最高。** GPTZero 在 ICLR 2026 的两万篇投稿里只扫了 300 篇就确认 50 多个幻觉引用，而每篇都已过 3–5 位人类审稿人；NeurIPS 2025 已录用论文里又查出 100 多个，66% 完全凭空捏造。做法很朴素，参考文献逐条丢 Google Scholar 或解析 DOI。但参考文献列表严格说也算稿件的一部分，第一档下仍不能上传。
5. **去 AI 味的正解是每条意见指到具体位置，不是改文风。** 2026 年的研究（arXiv 2603.20450）发现五种主流检测器都会把「人写加 LLM 润色」的评审误判成 AI 生成，「允许润色」类政策事实上无法执行。带页码、节号、图号、公式编号的句子只有读过论文的人写得出来，这是目前唯一可靠的手段。
6. **图的 AI 痕迹只能靠肉眼。** Imagetwin、Proofig 是机构级订阅工具，个人审稿人用不到；通用 AI 图像检测器在科学图上不可靠。可用信号是图内文字有没有乱码生造词、图注跟图对不对得上、曲线是不是过于平滑、有没有误差棒。

## 主会话验收记录

### 一、政策与数据逐条回原页核对

用 curl / python 直接抓原页，不经子 agent 转述：

- **ICML 2026 违规处理博客**：795 条违规评审、506 名审稿人，其中 398 名互惠审稿人的 497 篇投稿被 desk reject。三个数字均与原页一致。
- **ICLR 2026 博客**：低质 LLM 评审者自己的投稿会被 desk reject，处罚落点与 ICML 一致。
- **NeurIPS 2026 实验页**：原文 "does not sanction any other use of LLMs"，即除官方 AI 辅助评审实验之外不认可任何其他 LLM 用法。
- **ARR 审稿人指南**：原文要求审稿人 "write ... by themselves"；并明文写了连自己写的评审报告也不得上传到非隐私保护的工具。
- **Elsevier 政策页**：不鼓励用 AI 辅助评审本身，理由是评审所需的批判性思维超出该技术范围。
- **arXiv 2603.20450**：标题为 "Policies Permitting LLM Use for Polishing Peer Reviews Are Currently Not Enforceable"，标题本身就是结论，可直接引用。
- **arXiv 2504.09737**：约 27% 的审稿人据反馈修改了评审，采纳建议 12000 条以上（报告里写的 26.6% / 12222 条是原文精确值）。
- **GPTZero ICLR 2026**：在两万篇投稿里只扫了 300 篇。抽样规模确认，不是全量扫描，引用时不要说成全量。
- **Frontiers 调查**：53%，n = 1645。

`survey/02` 推荐清单里的七个仓库，star 数、最近 push 时间、许可证全部走 GitHub API 核实，不采信 README 上的自述。

### 二、总览初稿与原文不符的三处，已改

1. **CVPR 的离线模型表述。** 初稿只说 ECCV 点名了离线模型。核对发现 CVPR 2026 原文同样写了 "e.g., an offline system"，两家是同一套口径，已合并表述。
2. **ICML Policy B 的禁止项。** 初稿列的项数与原文对不上。原文是五项：问优缺点、让它列评审要点、让它列评审提纲、让它写整份评审、让它替你拟给作者的问题。原文**没有**列「总结论文」这一项，初稿多出来的那条已删。另外补上了原文对「隐私合规」给的三类例子：机构或企业的 API 订阅、明确关闭了训练数据使用的个人订阅、自托管模型。
3. **流水线在 ICML-B 档自相矛盾。** 初稿在第二档推荐跑 ARS `quick` 出问题清单，但 Policy B 的禁止项里明写不得让模型列评审要点、列提纲、拟问题——产出问题清单正是这件事。已改为：ICML-B 档整个跳过交叉检查这一步，不要用擦边问法绕；「让 AI 审我写完的意见」这一步在该档下只审语言（模糊表述、不专业措辞），删掉「对论文的误读」那半句，因为查误读要模型对论文内容作判断。操作卡第 6、8 条同步改了。

第 3 处是三处里最要紧的。它不是抄错数字，是推荐动作与它自己引的政策直接冲突，照着做就会违规。

### 三、ARS reviewer 审计的三条硬伤，grep 源码复核

`survey/03` 说 ARS `academic-paper-reviewer` 的 rubric 有三处硬伤，主会话 grep 插件源码逐条验过：

- `quality_rubrics.md` 第 54–57 行：证据充分性按参考文献数量计分。
- 同文件第 105 行：权重公式里写作质量只占 15%。
- 全插件检索：没有任何「AI 生成痕迹检测」维度的条目。

三条都属实，所以 `survey/00` 第四部分对这个 skill 的限定用法（只用 `quick` 且加约束 prompt、绝不跑 `calibration`）成立。
