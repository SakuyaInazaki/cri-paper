# 论文拆分方法调研：自动系统、人类方法论、主张—证据对齐、本地工具、图表清单

这份报告只回答一件事：**把一篇投稿拆成结构化清单，现有做法是怎么拆的**。不涉及怎么写审稿意见。合规档位沿用 `00` 第一部分的三档划分（档一全禁 / 档二隐私合规模型可读稿不可评判 / 档三只许润色），AI 痕迹识别的结论沿用 `01` §4，不重复。

最后一节（第六节）是对主会话那份九层草案的逐层差分意见。

### 1.1 OpenAIReview：目前唯一把"跨节一致性"做成机制的系统

[GitHub](https://github.com/ChicagoHAI/OpenAIReview)｜[项目页与博客](https://openaireview.org/blog.html)｜[UChicago DSI 介绍](https://datascience.uchicago.edu/insights/openaireview/)

四种策略：`zero_shot`（整篇一次性提问）、`local`（逐块加邻近上下文）、`progressive`（逐块 + running summary）、`progressive_full`（同上但返回合并前的全部意见）。

progressive 的做法：论文切成大致等长的 passage，逐段审；每段的上下文有两个来源，**邻近 passage 的窗口**和**到此为止的 running summary**；summary 累积 notation、definitions、key equations、theorems、assumptions、claims，每审完一段用一次单独的模型调用把新内容并进去；最后一次调用合并意见。设计目标写得很直白——不把整篇塞进一个 prompt，也要能抓到"某个符号的用法与几节之前的定义不符"这类跨页问题。

评测（Claude Opus 4.5）：zero_shot LLM recall 0%、约 \$0.3/篇；local 15.4%、约 \$1；progressive 25%、约 \$4、location coverage 83%；合并前的 progressive_full 是 **LLM recall 44.2%、location recall 86.5%**。副产品对草案极重要：**合并这一步把 recall 从 44.2% 砍到 25%**，去重归并不是免费的。

PDF 解析四引擎级联：Mistral OCR（云，\$0.001/页）→ DeepSeek OCR（本地，隐私选项）→ Marker（离线，数学好）→ pymupdf4llm（兜底）。输入支持 PDF / DOCX / .tex / Markdown / 纯文本 / arXiv HTML。

配套基准 [Benchmarking Agentic Review Systems, arXiv:2606.19749](https://arxiv.org/abs/2606.19749)（Nguyen, Hao, Elazar, Tan，2026-06-18）：论文质量排序最好 83.0%；**注入错误**检出（4 类错误、8 个 arXiv 学科）最好 71.6%，不同模型抓到的错误不同，集成后 recall 到 83.3%。真实部署里用户正评比负评 1.44:1，**抱怨集中在假阳性和琐碎问题**。

### 1.2 DeepReviewer-v2：锚点做得最实

[GitHub](https://github.com/ResearAI/DeepReviewer-v2)

管线 `PDF → MinerU markdown + 版面元数据 → review agent 工具循环 → final markdown → final PDF`。agent 的工具是 `pdf_read_lines`、`pdf_annotate`、`paper_search`，目的是让每条推理都落到可追溯的证据上。中间产物在 `data/jobs/<job_id>/`（markdown、token 用量、每工具调用次数、文献检索统计）。最终 PDF 带用量汇总、原文附录，并在 MinerU 给出行级 bounding box 时**自动把评审意见叠画在原文上**。需要 MinerU API token，严格说不是全离线；Python 3.11+，LLM 可指向任意 OpenAI 兼容端点。

### 1.3 AI-Scientist 与 openreviewer：两个"不拆"的反例

[SakanaAI/AI-Scientist](https://github.com/SakanaAI/AI-Scientist) 的 `ai_scientist/perform_review.py`：`load_paper()` 是三级兜底 `pymupdf4llm.to_markdown()` → `pymupdf` → `pypdf`，**没有任何结构化拆分**，整篇 markdown（可用 `num_pages` 截断）直接进 prompt。输出是 NeurIPS 评审表的 JSON：Summary / Strengths / Weaknesses / Originality / Quality / Clarity / Significance（1–4）/ Questions / Limitations / Ethical Concerns / Soundness / Presentation / Contribution（1–4）/ Overall（1–10）/ Confidence（1–5）/ Decision。有 `num_reflections` 自我批评迭代和 `num_reviews_ensemble` 多评审 + meta-reviewer 聚合；系统提示还有正/负偏置两版。

[maxidl/openreviewer](https://github.com/maxidl/openreviewer) 同样不拆：`pdf2md/` 用 Marker 转 markdown，整篇塞进 128k 上下文的微调 Llama-3.1-8B，按 ICLR2025 模板输出。仓库无许可证声明，法律上默认保留全部权利。

把这两家和 OpenAIReview 放一起看：**不拆 = 没有位置锚点 = 只能产出评分和泛化的 weakness**，这正是 `00` 第二部分说的"AI 只能挑表层问题"的机制解释。

### 1.4 PaperQA2：成熟的 chunk + 引用定位范式

[Future-House/paper-qa](https://github.com/Future-House/paper-qa)。分块大小 `parsing.chunk_size` 可配。每个 chunk 带**页码**、citation 和关联的图/表 media 对象（一对多）。解析器可选 PyPDF、Docling、Nvidia Nemotron，都报页码、支持 DPI。检索三段式：embedding top-k → LLM 重排 + 上下文摘要（产出它所谓的 "evidence"）→ `answer.evidence_relevance_score_cutoff` 过滤。价值不在审稿，在于**"chunk 带页码 + evidence 有相关性分数 + 低分丢弃"这一整套现成的证据定位工程**。

### 1.5 两个按维度并行拆的 Claude skill

[AlexWortega/ai-peer-review-skill](https://github.com/AlexWortega/ai-peer-review-skill)：默认 5 个并行 Claude subagent（可配 3–8），NATO 代号 alfa–echo，其中一个默认套 Neel Nanda 的 ML 论文评估框架（叙事强度、新颖性、baseline 比较、消融、可复现、统计严谨）。输出 `review_*.md` + 综合 meta-review（区分共识与独有）+ **concerns matrix CSV（哪个 reviewer 标了哪条）** + `results.json`。改编自 poldrack/ai-peer-review，用同模型多次并行代替多家专有模型。

[claesbackman/AI-research-feedback](https://github.com/claesbackman/AI-research-feedback) 的 `/review-paper`：**8 个并行 agent** = 拼写语法、内部一致性（交叉引用与术语）、无支撑的主张、数学（记号与公式）、表格与图、referee 评估、贡献 steelman、怀疑论 devil's advocate。第 7、8 号从对立立场给分，综合阶段找分歧的 crux。输出 `reviews/PRE_SUBMISSION_REVIEW_[YYYY-MM-DD].md`，自动版本化。面向经济学期刊，未指定时用通用标准。这 8 个维度本身就是一份拆分方案，和草案九层高度重合。

### 1.6 proofreading：现成的 100+ 项清单

[JakobThumm/proofreading](https://github.com/JakobThumm/proofreading)。6 类：Paper Structure、Math Symbols and Notation、Statistical Relevance、Figures and Tables、Grammar and Style、Abbreviations。每条带 severity（`[ERROR]` 规则违反 / `[WARN]` 需人判断 / `[INFO]` 小建议）和难度（`[HARD]`/`[MIX]`/`[VIBE]`）。Step 0 先收集 LaTeX 源并跟着 `\input`/`\include` 链拼出逻辑全文，无源码时退到纯文本/PDF（批注抽取用 pymupdf）。两种模式：report（scorecard + top issues + 按 severity 与行号分组）与 `--interactive`（逐条修，每修一条重读文件处理行号漂移）。

代表性条目直接可抄：摘要必须按"动机 → gap → 方法 → 定量结果"顺序；intro 的贡献必须是以 "We" 开头的**可证伪列表**；每个符号（含上下标索引）首次使用前必须有散文定义；结果图必须有不确定性可视化，除非明确给出理由；缩写首次出现用 `full term (ABBREV)`；表格用 booktabs 不用 `\hline`。

## 二、人类审稿方法论里的拆分

### 2.1 Keshav 三遍法（[SIGCOMM CCR 原文](https://dl.acm.org/doi/10.1145/1273445.1273458)）

**第一遍，5–10 分钟**：认真读标题、摘要、引言；读各级小标题、忽略其余；读结论；扫参考文献把读过的勾掉。结束时要能回答 five Cs——Category（测量？对现有系统的分析？研究原型描述？）、Context（和哪些论文相关，用了什么理论基础）、Correctness（**假设看起来成立吗**）、Contributions、Clarity。他还补了一句：大多数审稿人和读者只会做一遍。

**第二遍，至多 1 小时**：忽略证明细节。原文点名两件事——(1)「仔细看图、示意图和插图，**特别注意 graph：坐标轴标注对不对？结果有没有误差棒使结论具有统计显著性？**这类常见错误会把赶工的粗糙工作和真正优秀的工作区分开」；(2) 标出相关但未读的参考文献。

**第三遍，新手 4–5 小时，熟手 1 小时**：核心动作是 "virtually re-implement"——按作者的假设把工作重做一遍，与论文对照，「识别并质疑每一条陈述里的每一个假设」。结束时能凭记忆重建全文结构，并**精确指出隐含假设、遗漏的相关工作引用、实验或分析技术的潜在问题**。

**文献综述三步**：Scholar 找 3–5 篇近作各做一遍 pass 1 并读其 related work → 在参考文献里找共享引用和重复出现的作者名（关键论文与关键人）→ 去这些人常发的顶会扫近期 proceedings。

可直接转清单的：five Cs 是一张五格表；pass 2 的"轴标注 + 误差棒"是图表层最小集；pass 3 的"隐含假设 / 遗漏引用 / 实验技术问题"正好对应草案的第 3、7、5 层。

### 2.2 NeurIPS Paper Checklist（[2026 版全 16 条](https://neurips.cc/public/guides/PaperChecklist)）

这份本身就是一份可复现性拆分表，而且**它要求作者在 justification 里指到具体章节**——等于作者已经替你把"声称—位置"配好对了，你只需要去核。16 条：

1 Claims（摘要和引言的主张是否准确反映贡献与范围）｜2 Limitations（假设及其被违反时的鲁棒性是否充分讨论）｜3 Theory, Assumptions and Proofs（完整假设集 + 完整证明）｜4 Experimental Result Reproducibility｜5 Open Access to Data and Code｜6 Experimental Setting/Details（数据划分、超参及其选法）｜7 Experiment Statistical Significance（**是否恰当且定义正确地报告 error bar 或其他统计显著性信息**）｜8 Experiments Compute Resource｜9 Code of Ethics｜10 Broader Impacts｜11 Safeguards｜12 Licenses｜13 Assets｜14 Crowdsourcing and Research with Human Subjects｜15 IRB Approvals｜16 Declaration of LLM usage。

配套的 [ML Reproducibility Checklist v2.0](https://www.cs.mcgill.ca/~jpineau/ReproducibilityChecklist.pdf)（Pineau，2020-04-07）分 5 组，粒度更细，适合做实验层的字段模板：**模型与算法**（数学设定/算法/模型的清晰描述、假设的清晰说明、复杂度分析）；**理论主张**（清晰陈述 + 完整证明）；**数据集**（样本数等统计量、train/val/test 划分细节、被排除的数据与全部预处理步骤、可下载链接、新采集数据的流程与质控）；**代码**（依赖、训练代码、评估代码、预训练模型、README 含结果表与复现命令）；**实验结果**（超参搜索范围 + 选择方法 + 最终全部超参、训练与评估运行的确切次数、统计量的明确定义、中心趋势与变异性、平均运行时或估计能耗、计算基础设施）。

### 2.3 会议 reviewer instructions 里的阅读顺序与检查项

**ICML 2026**（[Reviewer Instructions](https://icml.cc/Conferences/2026/ReviewerInstructions)）是 8 步：先（重）读评审表 → 「carefully, critically, and with empathy」地读 → 「think carefully about whether the paper has properly substantiated the claimed contributions」→ 放进研究图景里定位 → 填表 → 读并回应 response → 与 AC 讨论 → rebuttal 后写最终理由。表单：Summary / Strengths and Weaknesses / Soundness(4) / Presentation(4) / Significance(4) / Originality(4) / Key Questions for Authors / Limitations / Overall Recommendation(1–6) / Confidence(1–5) / Ethical Concerns / LLM Policy Compliance / CoC / Final Justification。显式检查项：主张是否被理论分析或实验结果支撑；证明是否正确且假设合理；实验设计是否良好；是否引入新任务/方法/理论/数据/视角，或**已有技术的新颖组合**；信息是否足以让专家复现；局限与负面社会影响是否充分讨论。

**ICLR 2026**（[Reviewer Guide](https://iclr.cc/Conferences/2026/ReviewerGuide)）压成**四问**：(1) 解决的具体问题是什么？(2) 方法是否动机充分、是否恰当地置于文献之中？(3) 证据是否支持主张、结果是否正确而严谨？(4) 意义与对社区的价值？另含独立的 Code of Ethics 报告（两问表单）。

**CVPR 2026**（[Reviewer Guidelines](https://cvpr.thecvf.com/Conferences/2026/ReviewerGuidelines)）：先查 COI、读作者指南、分几天读完、**补充材料只在为理解贡献所必需时才看**。好评审要引用具体技术内容、声称存在 prior work 必须给出具体文献、给可执行建议。不负责任评审四判据：过短且不引用具体技术内容 / 通用到可套任何投稿 / 对方法或结果有可证伪的事实错误 / LLM 生成或大幅辅助。可选查代码但不强制。

**ACL ARR**（[Reviewer Guidelines](https://aclrollingreview.org/reviewerguidelines)）表单字段：Paper Summary、Summary of Strengths、Summary of Weaknesses、Comments/Suggestions/Typos、Soundness、Excitement（与 soundness 正交，允许纯主观）、Overall Assessment、Confidence、Reproducibility、Ethical Concerns / Needs Ethics Review。另有 **H1–H17 不良启发式清单**（斥为"显然"而不确认社区是否已知、与预期不符就否定、把 SOTA 当必要条件、歧视负结果、批评方法"太简单"、要求用自己偏好的方法、看不起小众课题、要求单语工作普适、索要大量非必需实验等），是一份反向检查表。

**Nature**（[For Referees](https://www.nature.com/nature/for-referees)）：可接受的论文要构成能影响领域思路的认识推进，并说明为何值得发在 Nature 而非更专门的期刊；报告首要用途是给编辑提供决策信息，其次是指导作者加强稿件；**若评审过程中借助了 AI 工具须在报告中透明声明**。（原页多次被 idp.nature.com 登录跳转挡住，见未核实清单。）

## 三、主张—证据对齐（claim–evidence alignment）

这一支 2020 年后的代表性工作，按"能不能直接用"排序。

**RIGOURATE**（[arXiv:2601.04350](https://arxiv.org/abs/2601.04350)，James / Xiao / Li / Moosavi / Lin，2026-01）——最贴题的一篇。两个任务：evidence retrieval（为一条 claim 找论文里的支撑证据）和 overstatement detection（给"措辞超出证据支持程度"打分）。数据是从 ICLR/NeurIPS 论文构造的 **10K+ claim–evidence 组**，8 个 LLM 标注、用同行评审意见校准。方法是微调 reranker 做检索 + 微调模型预测 overstatement 分数并给理由。是否开源 abstract 页未写明。

**贡献声明抽取**：[SemEval-2021 Task 11 NLPContributionGraph](https://aclanthology.org/2021.semeval-1.44/)（D'Souza & Auer）定义三粒度——贡献句 → 科学术语与谓词短语 → (subject, predicate, object) 三元组，再把三元组归入若干 Information Unit；并明确指出**贡献陈述通常取自 introduction 而非 abstract**。系统例：[UIUC_BioNLP, arXiv:2105.05435](https://arxiv.org/pdf/2105.05435)。通用侧还有微软的 [Claimify](https://www.microsoft.com/en-us/research/blog/claimify-extracting-high-quality-claims-from-language-model-outputs/)（ACL 2025）。

**摘要数字 ↔ 正文表格一致性**：[arXiVeri, arXiv:2306.07968](https://arxiv.org/abs/2306.07968)（Shin, Xie, Albanie，2023-06）提出 AutoTV，拆成两个子任务——**table matching**（在被引文献里找到对应源表）和 **cell matching**（定位共享单元格并给出准确行列索引）。它指出的困难点值得抄进清单：科学论文的表是给人看的不是给机器解析的，版式差异大，同一个数可能以百分比/分数/小数、不同精度出现。连 GPT-4 也很吃力。

**表格 claim 验证与伪造检测**：[Atomic Reasoning for Scientific Table Claim Verification, arXiv:2506.06972](https://arxiv.org/html/2506.06972v1) 的数据构造方式有启发——改动阈值、量级、单位来生成"被反驳的 claim"，形式不变而与表格数据矛盾。[TAB-AUDIT, arXiv:2603.19712](https://arxiv.org/html/2603.19712) 检测 AI 伪造的表格，关键发现是"伪造表的数字不是孤立地异常，而是相对于一个在别处完全常规的科学骨架异常"。

**over-claiming 的医学前身**：这问题在生物医学里叫 **spin**，方法论成熟得多。[DeSpin](https://aclanthology.org/2020.bionlp-1.5.pdf)（BioNLP 2020）是规则 + 机器学习的原型系统。可直接借用的判据：「结论为正面，但不反映所报告的准确性估计」（诊断准确性研究的摘要里占 49%）、「结论为正面，但未考虑高偏倚风险或适用性问题」（42%）、**方法与结果两节之间因选择性报告而不一致**、标题/摘要/结果/讨论里使用过强的引导性措辞。

**纯算术的自洽检查（非 LLM，全禁档可跑）**：[statcheck](https://cran.r-project.org/web/packages/statcheck/) R 包（Nuijten）从文章抽取以 APA 格式完整报告的 NHST 结果（t、F、r、z、χ²、Q），**用报告的统计量和自由度重算 p 值**并与报告值比对；高影响力心理学期刊中每八篇就有一篇存在会影响统计结论的严重不一致。[GRIM 检验](https://en.wikipedia.org/wiki/GRIM_test)（Brown & Heathers 2016）：对整数数据，均值必须能写成分母为 N 的分数，故均值 + 样本量 + 构成题数存在硬约束；可测的 71 篇里约半数（36）至少一处不可能的均值，>20%（16）有多处；R 包 `scrutiny` 另有扩展到标准差的 GRIMMER。这两条的价值不在"能抓造假"，在于**纯本地、零 LLM、零外发**。

**GROBID 是这一层的地基。** 端点：`processHeaderDocument`（标题/作者/摘要，可出 BibTeX）、`processFulltextDocument`、`processReferences`、`processCitationList`、`processCitation`、`referenceAnnotations`（带 PDF 坐标的 JSON）、`processFulltextAssetDocument`（把图表作为图片资源抽出）。关键参数 `teiCoordinates` 可让 `persName`、`figure`、`ref`、`biblStruct`、`formula`、`s`（句子）携带 PDF 坐标——**这就是现成的位置锚点体系**。坑：源码构建要 OpenJDK 21，用 Docker 最省事；官方只保证 Linux 64 位和 macOS（Intel 与 ARM）。**合规红线在 `consolidateHeader` / `consolidateCitations` / `consolidateFunders`，开启后会调 Crossref REST API 或 biblio-glutton 做外部元数据富集（DOI/PMID 解析 F1 > 0.95）。默认关，第一档下必须保持关。**

### 4.1 参考文献核真：API 需不需要 key、算不算外发（重点核实）

**Crossref REST API**（[官方 access-and-authentication 页](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/)）——原话：「Anyone can access the REST API, no signup or registration is required.」**不需要 key**。三个池：Public（不认证，5 请求/间隔，1 并发）；Polite（在 `mailto` 参数或 `agent` header 里带邮箱，10 请求/间隔，3 并发，官方推荐）；Plus（Metadata Plus 订阅，`Crossref-Plus-API-Token: Bearer <key>`，150 请求/间隔）。超限返回 429，限流通常自动施加与解除。

**OpenAlex 的情况在 2026-02-24 变了**（[官方博客](https://blog.openalex.org/openalex-api-new-features-and-usage-based-pricing/)）：改为按量计费。「Every API key gets **\$1 of free usage per day**」；「You can still make a few calls without an API key for demo purposes, but it's not suitable for any kind of production use.」单篇 work 的精确 lookup 免费，list/filter \$0.0001/次，**search \$0.001/次**，PDF/XML 下载 \$0.01/次。旧文档里的"10 万次/天、10 请求/秒、mailto 礼貌池"已作废。结论：**现在核真参考文献用 Crossref 比用 OpenAlex 干净——Crossref 真的不用注册，OpenAlex 实际上需要一个免费 key，而按标题 search 正好是收费动作。**

**Semantic Scholar**（[产品页](https://www.semanticscholar.org/product/api)）：无 key 可用，但所有匿名调用共享一个 1000 请求/秒的全球池，高峰会被限流；申请个人 key 后起步是 1 请求/秒（可申请上调）。key 通过表单申请、邮件发放。

**"算不算把稿件内容外发"——我的判断，供你拍板。**

分三件事看：(1) **按 DOI 查**——DOI 是公开标识符，稿件里本就明文写着，指向的是别人已发表的公开文献；对方只看到"有人查了某篇公开论文"，和任何读者查同一篇没有区别，泄露量最小。(2) **按标题+作者串查（`query.bibliographic`）**——发出去的仍是别人已发表文献的元数据，不是投稿内容，但比 DOI 多泄露一点：对方能看出你在**核对**。(3) **真正外发的是"关联事实"**——某个 IP（走 polite pool 还有某个邮箱）在某时刻把这一组特定文献逐条查了一遍，这组组合就是这篇投稿的**引用指纹**；稿子日后发表，指纹可对上。

所以 `00` 说的"档一不做引用核查"我支持，但理由不是"喂给了 LLM"，而是引用指纹构成稿件信息外发。补一条**档一非做不可时的最小化做法**：只用 DOI 解析（doi.org content negotiation 或 Crossref 按 DOI 精确查），不用标题 search；不带 `mailto`（放弃 polite pool，换取不把邮箱写进对方日志）；逐条间隔发送而非批量并发。这仍是外发，只是量级最小。Crossref / OpenAlex 是否留存查询日志，两家文档都没声明，标未核实。

## 五、图表逐张检查清单

在 `01` §4.3 已有的四条（图内乱码或生造词 / 图注与图不符 / 曲线过平滑无噪声 / 无误差棒）之外，下面是可以逐张打勾的补充条目，按来源分组。

**A. 出版界的图像完整性（[Nature Portfolio Image integrity and standards](https://www.nature.com/nature-portfolio/editorial-policies/image-integrity)）**
1. 图内是否有重复的区块（同一图内或跨图/跨 panel）。
2. blot 和 gel 是否有 lane 拼接（splicing）的痕迹。
3. 是否标明哪些 panel 是 sample processing 或 loading control。
4. 提供的未处理原始扫描件与正文图是否对得上。
5. 亮度/对比度/放大等调整是否作用于**整幅图**、并对同一图内同类型图像**等同施加**；是否避免了阈值操作、信号范围的扩张或压缩、对高信号的改动。
6. 伪彩与非线性调整（如 gamma）是否明确披露；处理软件与增强技术是否写进 methods。
7. 生命科学论文的 gel/western blot 未处理原图是否随终稿提交。编辑可在评审期间索要未处理数据，拿不到可中止评审。

**B. Elisabeth Bik 的筛查方法与三类重复**（[The Scientist 访谈](https://www.the-scientist.com/data-integrity-in-scientific-research-insights-from-elisabeth-bik-73119)）
8. 三类重复分开写：简单重复（可能是诚实错误，最轻）；**带重叠、旋转或拉伸的重复，以及同一张图内的元素重复**（明确的数据操纵）；splicing（把两张图拼成一张）。
9. 她的初筛不用任何软件，就是快速把所有图翻一遍；可疑时下载图、用 macOS 的 Preview 调颜色和亮度看——个人审稿人完全可复制，也印证 `01` 的结论（别指望 Imagetwin/Proofig）。
10. **审稿人最容易略过的是复杂的多 panel 图**，重复恰恰藏在那里。把"panel 数 ≥ 4 的图强制逐 panel 看"写进清单。

**C. COPE / ICMJE**
11. ICMJE 把欺骗性图像操纵列为与捏造、篡改并列的科研不端；COPE 有 image manipulation 的 eLearning 模块与给编辑的处置流程（更正/关注声明/撤稿），并要求审稿人具备批判性评估图像数据质量与原创性的能力（[COPE](https://publicationethics.org/guidance/seminar-and-webinar/image-manipulation)）。清单里应有一格：这条发现属于"要求作者澄清"还是"要转给编辑走完整性流程"。

**D. ML 社区的图表条目**
12. 坐标轴是否正确标注（单位、量纲、变量名）——Keshav pass 2 原话。
13. 结果是否带误差棒或其他统计显著性信息且**定义正确**——NeurIPS checklist Q7。
14. 误差棒语义是否写明：SD 还是 SEM？变异来源是什么（train/test 划分、初始化、随机种子）？计算方法是否说明？运行了几个 seed？阴影带代表什么？——ML Repro Checklist。
15. 非对称分布是否用了对称误差棒，以至画出越界值（例如负的错误率）。
16. 每张图表是否都被正文引用过；caption 是否自足（不读正文也能看懂）——proofreading 机械检查项。
17. 结果图若无不确定性可视化，作者是否明确给出了理由——proofreading `[WARN]` 级。
18. y 轴是否被截断。已有实验证明轴截断会让读者高估差异，且**即使事先被告知仍然生效**（83.5% 受试）。
19. 是否违反比例墨水原则（阴影面积与其代表的量不成比例）；学术条形图里约 5% 有此问题。
20. 纵横比是否被拉伸以夸大趋势；坐标轴是否被反转；对数轴是否标注清楚。
21. 同一量在不同图表间的精度与单位是否一致（百分比/分数/小数混用）——arXiVeri 点名的经典坑。

## 六、对九层草案的逐层差分意见

先给总的三句话。第一，**草案的九层在现有做法里基本都能找到对应，最缺的不是层，而是"锚点 ID 体系"这个横切决定**。第二，**"跨节一致性核对"不能放在最后当一个步骤，它必须是顺序遍历时维护的状态**，OpenAIReview 的数字证明了这一点。第三，**每层必须设条数上限**，不然假阳性会把清单变成负担（2606.19749 的真实部署抱怨就是假阳性和琐碎问题）。

下面逐层。

**第 1 层 元信息与版面。** 有现成做法（GROBID `processHeaderDocument`）。建议增字段：总页数与是否超限、是否存在匿名性破坏（致谢、资金、作者信息、指向作者仓库的链接）、补充材料是否存在（CVPR 明说"只在必要时看"，所以要先记一笔"看没看"）、参考文献条数。机械部分：`pdftotext -layout` 数页 + GROBID header + pdfplumber 查版式。

**第 2 层 贡献声明与其声称的证据位置。** 承重墙，支持最强也最该改。建议：(a) 借 NLPContributionGraph 的三粒度，先抽**贡献句**（它的经验是贡献句在 introduction 而非 abstract），再压成短语，最后写成 (主语, 谓词, 宾语)；(b) 每条贡献强制配一个 `evidence_locator`（§N / 表 X / 图 Y / 定理 Z），**配不上的直接标红**——这正是 NeurIPS checklist 让作者做的事，你只需去核；(c) 增一个三档 overstatement 字段（完全支持 / 部分支持 / 超出证据），思路取自 RIGOURATE 与医学侧 spin 判据；(d) 单独列一行「摘要里每一个数字 → 它在正文哪张表的哪一格」，即 arXiVeri 的 cell matching。机械部分：正则抓摘要数字 + pdfplumber 抽表格数字做候选匹配，剩下人工确认。

**第 3 层 问题设定与定义。** 建议从"散条目"改成**一张符号表**：符号 → 定义位置 → 使用位置列表 → 是否冲突。依据是 OpenAIReview 的 running summary 累积的正是 notation / definitions / equations / theorems / assumptions，以及 proofreading 的硬规则「每个符号（含上下标索引）首次使用前必须有散文定义」。另外**假设要单独一列**：Keshav 的 Correctness 就是"假设看起来成立吗"，pass 3 更要求"质疑每条陈述里的每个假设"。

**第 4 层 方法与新颖点。** 新颖点字段成对写：「作者声称的 delta」和「你能找到的最近邻工作 + 具体文献」——CVPR 2026 明文要求"声称存在 prior work 必须给出具体文献"，不给就是不负责任评审。同时把 ARR 的 H 系列挂在这一层做负面约束，尤其「批评方法太简单」和「把 SOTA 当必要条件」两条，ICML 也明确承认"已有技术的新颖组合"算原创性。

**第 5 层 实验清单。** 字段直接抄 ML Repro Checklist v2.0 的第 3、5 组，不必自创。**强烈建议增一个草案没有的字段：这张表里每个 baseline 数字是自己跑的还是从原论文抄的。** 抄表是 arXiVeri 那类错误的入口，也是最容易问出高质量问题的地方。

**第 6 层 图表逐张清单。** 机械支撑最好：pdffigures2 一跑就得到每张图的 page / bbox / caption / 图号 / 类型，**清单骨架可自动生成，你只填判断栏**；GROBID 的 `teiCoordinates=figure` 是备选。字段照第五节的 21 条挑，按领域裁剪（生物医学取 A+B，ML 取 D）。补一条：panel 数 ≥ 4 的图强制逐 panel 过。注意 pdffigures2 会主动排除"摘要上方的图"，teaser figure 得手工补。

**第 7 层 相关工作与参考文献核真。** 建议**拆成两栏**：存在性（能否解析到 DOI、能否在 Crossref 命中）与归属正确性（作者 / 年份 / venue 是否被从多篇真实文献拼接而来）。依据是 `01` §4.2 的 66% 属于完全捏造——单靠存在性这一栏就能拦下大多数。这一层要在 skill 里做成**显式开关**，默认随合规档位关闭（档一关），并在 UI 上写清"开启会向 Crossref 发出引用指纹"。机械部分：GROBID `processReferences` 出结构化条目 → 自写脚本按 DOI 走 Crossref 公共池，**不要用 GROBID 的 `consolidateCitations`**，因为它把外发动作藏在解析步骤里，容易在档一误触。

**第 8 层 写作与表达。** proofreading 的 100+ 条可直接引入，但**只保留 `[ERROR]` 级和图表相关的 `[WARN]`**，其余会把清单淹掉。真正要小心的是这一层最容易产生假阳性，而 CVPR 又明确把"可证伪的事实错误"列为不负责任评审——机器标出来的写作问题若不逐条核实就写进意见，风险不对称。机械部分：如果拿得到 LaTeX 源就用 proofreading 的 Step 0（跟 `\input` 链）；只有 PDF 时退到 pdftotext + 自写正则。

**第 9 层 可复现与伦理。** 不要自己设计，直接用 NeurIPS 2026 的 16 条 + ML Repro Checklist v2.0。理由是：NeurIPS 的投稿本身就带这份 checklist 且要求作者指到章节，你的清单和它同构时，核对成本最低。

**第 10 项 跨节一致性核对。** 唯一需要改机制的地方。OpenAIReview 的证据是：合并前 LLM recall 44.2% / location recall 86.5%，合并后掉到 25%。两条推论——(a) 一致性检查必须是"顺序过一遍、边过边维护 running summary"，不能是"读完全文最后问一句"；(b) 如果你的方案里有"归并同类意见"的环节，**要保留合并前的原始条目**，因为归并会吃掉一半发现。

### 草案漏掉的层

**(a) 锚点 ID 体系（应当是第 0 层）。** 草案九层都假定"能指到具体位置"，但没规定位置怎么写。建议在拆分之前先定死一套唯一 ID：`页码 + 节号 + 图/表号 + （可选）bbox`。GROBID 的 `teiCoordinates`、pdffigures2 的 bbox、MinerU 的 `middle.json`、PaperQA2 的 chunk 页码都能供给，但**只能选一套当主键**，混用会让第 6 层和第 10 层对不上。这件事不定，后面每条意见指位置都要重新发明一次。

**(b) 数值一致性层（建议从第 10 项里独立出来）。** 摘要 ↔ 正文 ↔ 表 ↔ 图 的数字对账，工具形态和语义一致性完全不同：它大半可以用**纯本地非 LLM**手段做（pdfplumber 抽表格数字 + 正则抓摘要数字 + statcheck / GRIM 这类算术自洽检查），因此在第一档下**照样能跑**。这是全禁档位里少数还能自动化的东西，值得单列一层。

**(c) 作者自填材料的对账层。** NeurIPS 投稿自带 checklist（16 条，每条要求指到章节），ICML/ICLR 有独立的 Limitations 字段，很多期刊有 data/code availability 声明。作者已经写好"见 §5"，你只要去 §5 核一下对不对。命中率高、成本近乎零，草案完全没有这一层。

**(d) 每层的输出预算。** 建议每层写死"最多 N 条"。依据是 2606.19749 的真实部署数据：用户正评比负评 1.44:1，抱怨集中在假阳性和琐碎问题。同一篇文章还给了另一条可用结论——不同模型抓到的错误不同，集成后 recall 从 71.6% 升到 83.3%；如果你的档位允许多跑几次，**多次独立运行取并集**比单次调得更细更划算，而 AlexWortega 那份 skill 的 concerns matrix CSV（哪个 reviewer 标了哪条）正是记录这种并集的现成格式。
