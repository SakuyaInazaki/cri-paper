# 实测记录：arXiv 2504.09737

测试稿：Thakkar et al., *Can LLM feedback enhance review quality? A randomized study of 20K reviews at ICLR 2025*，
arXiv:2504.09737v1（公开论文，30 页，7.4 MB）。PDF 未入库，实测时自行下载：

```bash
curl -L -o 2504.09737.pdf https://arxiv.org/pdf/2504.09737
```

日期 2026-09-11。三个脚本各跑一遍，全部无报错退出。本文件只记录**脚本输出**与**已知缺陷**，不含任何审稿判断。

## 1. `pdf_skeleton.py`（零网络零 LLM）

```bash
python3 scripts/pdf_skeleton.py 2504.09737.pdf -o examples/2504.09737-skeleton.md
# 统计：页数 30 ／ 参考文献 45 条 ／ 图表 11 个 ／ 贡献句 3 条 ／ 摘要数字 5 个
```

产物见 [`2504.09737-skeleton.md`](2504.09737-skeleton.md)。耗时 0.4 秒。

**表头已对齐模板 v1.1**（规格 §6 裁定 1）：第 1/7/10 层六列，第 2 层七列（含 `evidence_locator`），
第 6 层十列 `fig_id | anchor | type | caption | cited_at | fact | judgement | severity | confidence | action`；
其余字段在 `fact` 栏按 `key=value; key=value` 打包，键名用规格原名。

| 层 | 抓到什么 |
|---|---|
| 第 1 层 | 30 页；参考文献 45 条（p14 起）；Supplementary/Appendix 命中 11 处；Checklist 命中 12 处；Limitations 命中 7 处；未检测到 data/code availability 声明；代码链接 1 条（p1 的 github.com/zou-group/…）；匿名性破坏候选 2 条（p14 的 Acknowledgements、p1 指向具名 owner `zou-group` 的仓库链接） |
| 第 2 层 | 贡献句 3 条，全在 p2（`we introduce` / `we develop` / `we present` 各 1） |
| 第 6 层 | 11 个图表编号：Fig1–Fig6、FigS1、FigS2、Tab1–Tab3；其中 9 个抓到 caption 首句与页码，Fig6 与 Tab3 只有正文引用没有 caption；正文引用次数与页码逐个列出，无"未被引用"的图表 |
| 第 7 层 | 45 条原始参考文献逐条成行，`fact` 打包成 `ref_id=Ref1; raw=…; exists=未查; attribution_ok=未查`（核真开关默认关，按规格 §6 裁定 8 写"未查"），`check_refs.py` 直接读 `raw=` 字段 |
| 第 10 层 | 摘要数字 5 个（`2025`、`20,000`、`27%`、`12,000`、`80`），其中 `12,000` 在正文各页找不到同一数字 |

### 已知缺陷（本篇实测暴露的，未修）

1. **URL 被空格截断。** p1 的 `https://github.com/zou-group/review_feedback_agent` 经 `pdftotext` 后下划线变成空格，脚本只截到 `…/review`。已在 fact 栏附上"原行"全文供人补全，但链接字段本身是错的。
2. **Fig6 / Tab3 无 caption 是真实情况，不是漏抓。** 这两个编号只出现在附录里被引用的**示例审稿意见文本**中（讲的是别人论文的 Figure 6 / Table 3），本文并没有第 6 张图和第 3 张表。脚本无法区分"本文的图表编号"与"引文里提到的别人的图表编号"，这类噪声要人工剔。
3. **图内文字会被当成正文引用。** Fig4 的引用页码里有 p3，而 p3 是 Fig1 的插图页——插图内部印着 "In Figure 4, the…" 的示意文本，被 `pdftotext` 抽了出来。
4. **合并引用抓不全。** "Figures 3 and 4" 这种写法只会记到 Fig3。本篇没出现，但这是通用盲区。
5. **摘要数字含年份噪声。** `2025` 来自 "ICLR 2025"，不是结果数字，须人工剔除。已过滤纯页码行，页眉页脚数字不再混入。
6. **贡献句只有 3 条，因为这篇论文的引言里根本没有"Our contributions are…"式的列表。** 手工复核过引言全文（p2–p3），含 `contribut|we propose|we present|we introduce|our main` 的句子就只有这 3 条，属于抓全了而非抓漏。代价是"contributions 后项目符号"这条分支在本篇上没被触发（另用合成输入验证过该分支能正常工作）。
7. **参考文献条数曾被数成 68 条（真值 45 条），已修。** 原因是附录标题写作 `A     Agent Prompts`（单字母编号），
   旧的终止条件只认 `Appendix A` 式标题，于是把附录里 `1. … 4. Format is correct: …` 这类编号列表也当成了参考文献。
   现在终止条件加了单字母标题，并要求条目编号单调递增，编号回退即停。**这条是对齐模板时顺带发现的真 bug，不是排版噪声。**
8. **节号锚点在附录里会串。** 附录页的 `§2`、`§5` 是 prompt 正文里的编号行被 `HEADING_RE` 误判所致，正文（p1–p13）的节号锚点是对的。

## 2. `numeric_consistency.py`（零网络，pdfplumber 可选）

```bash
python3 scripts/numeric_consistency.py 2504.09737.pdf
# 统计：页数 30 ／ 摘要+结论数字 9 个 ／ 正文找不到 1 个 ／ 表格数字单元格 6
```

- 摘要定位 p1，结论/讨论定位 p13，均成功。
- 摘要数字 5 个 + 结论数字 4 个（`2025`、`27%`、`2010`、`50`）。
- **只在摘要出现、正文找不到的：`12,000`**（"over 12,000 feedback suggestions … were incorporated"）。人工 grep 全文确认属实：`12,000` 在正文里一次都没出现。这是脚本该报的那类线索，但**是否构成问题要人看**——正文可能用了别的口径（如按类别拆开的数字之和）。
- 表格匹配：`pdfplumber` 可用，但**全篇只切出 1 张表**（p9，3 行 1 列），共 6 个含数字单元格，与摘要/结论数字无候选匹配。

### 已知缺陷

1. **`pdfplumber` 默认的 lines 策略在这篇上基本失效。** Tab1（p10）、Tab2（p12）是 booktabs 风格，横线不成闭合框，`extract_tables()` 返回空。改用 `--table-strategy text` 会把正文段落误切成 51 行的"表"，噪声更大——所以默认保持 lines，并把这条写在输出头部。**这一层在这篇论文上等于没起作用**，表格数字对账只能人工做。
2. `2010`（NIPS 2010）、`2025`（ICLR 2025）、`50`（over 50 conferences）这类非结果数字混在列表里，须人工剔。
3. 结论段的起点靠 `Discussion|Conclusion` 行匹配，排版不同的稿件可能定位失败（脚本会在输出头部标"**失败**"）。

## 3. `check_refs.py`（**会外发**引用指纹）

### 3.1 默认参数、前 15 条

```bash
python3 scripts/check_refs.py examples/2504.09737-skeleton.md --limit 15
# 完成：无标识符 15
```

**15 条全部是"无标识符"，一个网络请求都没发出。** 这篇论文的参考文献表用的是不带 DOI、不带 arXiv 编号的紧凑格式（如 `[1] Bruce Alberts, … Science, 321(5885):15–15, 2008.`），
而默认模式按规格 §3 第 7 层只认 DOI 与 arXiv ID。命中 0、attribution_ok 全部"未核"。

这本身就是一条对 skill 有用的结论：**默认最小化模式对"引用表不写 DOI"的 ML 会议稿几乎无效**，
想核真就得开 `--title-search`，而那正是泄露更多的那一档。

### 3.2 开 `--title-search`（同样前 15 条，作为对照）

```bash
python3 scripts/check_refs.py examples/2504.09737-skeleton.md --limit 15 --title-search
# 完成：命中 8；未命中 7
# attribution_ok：一致 5；部分核对 2；不一致 1；未核 7
```

逐条要点：

- 命中且第一作者+年份一致：Ref7（Rogers, ACL Findings 2020）、Ref8（Rogers, ACL 2023）、Ref12（Liang, NEJM AI 2024）、Ref14（Madaan, Self-Refine）、Ref15（Hosseini, RIPR 2023）。
- 命中但只核到年份（Crossref 记录缺 author 字段）：Ref3（Publons 报告）、Ref9（Arns, Nature 2014）。
- 命中但标"不一致"：Ref1，Crossref top-1 是 2020 年的同名条目而原文写 2008 年——**这不是作者造假，是标题搜索撞了同名文献**，正说明标题搜索的结果必须人工复核。
- 未命中 7 条：ICLR 新闻稿、Anthropic 模型卡、Ejifcc 期刊文章、TextGrad 等仅在 arXiv 的预印本。Crossref 里确实没有或索引不佳。

### 已知缺陷

1. **标题搜索天然有假命中。** Crossref 的 `query.bibliographic` 总会返回最接近的一条，脚本加了词集相似度阈值（`--title-min-sim`，默认 0.6，含包含度兜底）把低相似度判为未命中，但 Ref1 这种同名撞车挡不住。
2. **本地标题靠启发式切出来**（按 `". "` 切段、取第一段小写词占比 ≥0.4 的），遇到 `[3] Publons. Global state of peer review 2018, 2018.` 这种"机构名当作者"的条目会把年份也带进标题。
3. **第一作者姓氏靠"首个逗号/and 之前的末词"**，遇到 `Serge P J M Horbach` 这类多缩写名或姓在前的风格会取错，取错时 attribution 标"不一致"，属假阳性。
4. 运行中出现过一次 Crossref 瞬时 `URLError`，脚本按"查询失败"记账并继续，没有崩——但**"查询失败"不等于文献不存在**，重跑即可。
5. 年份差 1 一律记成"未核"并附说明（预印本与正式发表常见），不当作不一致。
