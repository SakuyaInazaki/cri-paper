# 可复制 prompt 集

用之前先确认当前模式。每段前面都写了它在哪个模式下能用。

## 一、U 模式的提取式提示

U 模式（ICML Policy B 型）允许把稿件喂给隐私合规模型帮助理解论文，但不许把评判委托给模型（见 survey/01 §2）。所以提示词的措辞必须是提取式，问的是「稿件里写了什么、写在哪」，不能是「这里有什么问题、好不好、缺什么」。

模型的输出只进论文卡的 `fact` 栏，`judgement` 及其后各列留空。

**第 2 层 贡献声明**

```
从引言部分逐条摘出作者声明的贡献句，只要原话，不要改写，不要归纳。
每条给出页码与节号。同时对每条标出作者把证据指向了哪个位置（§ / Tab / Fig / Thm）。
作者没有指向任何位置的，写 evidence_locator: 无。
不要评价这些贡献是否成立。
```

**第 3 层 符号与假设**

```
列出 §3 定义的全部符号：符号本身、定义出现在哪一页哪一节、后续在哪些位置被使用。
另外把全文里以 assume / suppose / we assume that 形式出现的假设句逐条摘原话，各带页码与节号。
只做提取，不要判断符号是否冲突、假设是否合理。
```

**第 5 层 实验清单**

```
从实验部分提取下列事实，每项带页码与表号或图号：
数据集名称与划分方式；每个基线的名称，以及原文是否说明该基线数字是自跑还是引自原文；
指标名称与定义位置；seed 数与方差报告的原话；计算预算与硬件的原话；
超参搜索范围；消融实验覆盖了哪些组件。
原文没写的项写「未写明」，不要推测，不要评价实验是否充分。
```

**第 6 层 图表事实（文本管线部分）**

```
列出全文所有 Figure 与 Table 的编号、所在页码、caption 首句，
以及每个编号在正文里被引用的位置。只做提取，不要评价图表质量。
```

**第 6 层 图页事实提取（看原 PDF 页，U 模式可用，M 模式不可用）**

规格 §6 第 7 条允许 U 模式把图页交给模型做事实提取，依据是 ICML Policy B 原文允许把稿件喂给隐私合规模型并用于理解论文。判断栏仍由人填。

```
这是稿件第 N 页。请只做事实转录，不要评价：
1. 图内出现的全部文字，逐字转录，包括轴标注、图例、panel 标号、图内注释；
2. 每条轴的变量名与单位，以及轴的起止值；
3. 图例有哪些条目，各对应什么；
4. 有没有误差棒或阴影带，caption 或图内有没有写明它代表什么；
5. 这张图分成几个 panel，各是什么类型（折线、柱状、散点、热图、显微图、示意图）；
6. 用一句话描述图里画的是什么量对什么量。
不要判断曲线是否过于平滑、轴是否被截断、是否像 AI 生成，那几项我自己看。
```

## 二、让 AI 审我写完的意见

第一档不可做。第二、三档可做，第三档若是 ARR 这类还要求工具本身隐私保护。这是唯一有大规模随机对照证据支持的用法（见 survey/01 §1.1、§5.2）。

通用版：

```
下面是我自己写完的几条审稿意见。请只做一件事：指出其中的模糊表述、
对论文的误读、以及不专业的措辞。不要帮我改写，不要补充新的意见，
不要给评分。
```

ICML Policy B 版（去掉「对论文的误读」半句，因为查误读要模型对论文内容作判断，那是这一档禁的事，见 survey/00 第三部分第 2 步）：

```
下面是我自己写完的几条审稿意见。请只做一件事：指出其中的模糊表述
和不专业的措辞。不要帮我改写，不要补充新的意见，不要给评分。
```

## 三、ARS quick 约束 prompt

只在政策用宽口径「辅助评审」措辞、且不禁止让模型列问题时用，也就是 F 模式。ICML Policy B 型的会议一律不要用，产出问题清单正是那一档明文禁止的事。原样取自 survey/03 §2.9。

```
/ars-reviewer quick

约束：
- 只跑 quick（field_analyst + eic），跳过 Phase 0 审稿人配置卡确认，直接出结果
- 不要 Editorial Decision Letter、不要 Revision Roadmap、不要 Phase 2.5 修订辅导
- 不要 0-100 评分表（证据充分性维度按文献数量计分，不适用于本文类型）
- 输出仅供我内部判断用：一个不超过 10 条的问题清单，每条一行，注明位置
- 额外补两个本 skill 没有的维度：(1) 图表质量（可读性、信息密度、是否有明显 AI 生成/拼贴痕迹）；(2) 全文是否有 AI 生成痕迹
- 不要写成审稿意见，最终意见我自己写
```

它给出的、它自己也说不清位置的条目一律丢掉。定位始终是「看我漏了什么」。绝不要跑 `calibration` 模式，它默认开跨模型，会把稿件发给另一家 provider（见 survey/03 §2.7）。

## 四、human-writing 调用 prompt

只用于中文意见改稿，只喂用户自己写的句子。原样取自 survey/03 §2.9。

```
使用 human-writing。这是短文改稿任务不是创作任务，跳过材料门槛检查，
只执行 references/revision.md 第三、四、五遍 + references/formats.md「短文」与「观点与评论」两节。
把下面的问题清单压成 3–4 条审稿意见，每条一句话，判断从正面下，不要冒号小标题，
不要破折号，不要"值得注意的是"这类路标，不要三项排比。
```

改完跑机械体检：

```bash
python3 ~/.claude/skills/human-writing/scripts/check_prose.py 意见.md
```

## 五、一句话披露模板

会议要求披露时用（ICLR 2026、Wiley 这类，见 `references/policy-tiers.md`）。照实填，不要夸大也不要缩小模型的参与程度。

```
本评审的论文阅读与判断由我本人完成，意见由我本人撰写。
AI 的参与限于：<按实际勾选>用隐私合规模型帮助理解 §X 的方法部分 /
用本地脚本做数值一致性与参考文献存在性核验 /
在我写完意见后请模型指出模糊表述与不专业措辞。
模型没有参与优缺点判断、评审要点拟定与意见初稿撰写。
```

如果实际只做了本地脚本这一档，就把前两句留着，第三句删掉，不要为了显得规范而写上没做过的步骤。
